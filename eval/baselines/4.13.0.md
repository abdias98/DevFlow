## 2. Run scorecards — not meaningful for this wave's new content

4.12.0 has real run scorecards (see `4.12.0.md` §2): both `/devflow-feature`
runs scored 100%, both bare runs matched the naive reference. Re-running the
**same two tasks** on 4.13.0 would reproduce those same numbers — neither task
exercises what Wave 20 actually added.

**Honest limitation:** `003-order-payment-lifecycle` and
`004-project-panel-tab` only probe state-transition, concurrency, ordering and
partial-failure classes — exactly what Wave 18–19 targeted. Neither task
touches a persisted schema/migration, calls an external integration with
retry/timeout semantics, or requires choosing (or rejecting) a tactical design
pattern. Scoring them again would show Wave 18–19's effect persisting, not
Wave 20's effect existing — and reporting that as evidence for Wave 20 would
be the same mistake as reading Wave 19 into a task designed for Wave 18. This
file does not do that.

**What Wave 20 needs instead:** new eval tasks whose naive/correct references
diverge specifically on `state-lifecycle.md`, `integration-consumption.md`,
`data-persistence.md` and `design-patterns.md` classes — e.g., a task whose
naive solution retries a non-idempotent external call with no timeout
(`integration-consumption.md` §1/§3), or one whose naive migration has no
rollback path for a breaking change (`data-persistence.md` §2). None exist yet
in `eval/tasks/`. Wave 21's PR26 (`feat/eval-behavioral-suite`) is where this
belongs.
