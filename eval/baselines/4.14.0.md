## 2. Run scorecards — not meaningful for this wave's new content

Same limitation as `4.13.0.md` §2, now compounded: neither existing eval task
exercises what Wave 21 added, and Wave 21 changed *verification mechanisms*
(escape analysis, runtime capability) rather than *review-time standards* — so
even a task redesigned for Wave 20's four new standards would not exercise
Wave 21's content either. Escape analysis has nothing to measure until a real
cycle produces an escape after this release ships; runtime verification only
activates at `deep`/`maximum` rigor with a qualifying externally observable
scenario, which none of the current fixtures declare.

**Deliberately deferred, by explicit user instruction:** Wave 21's own plan
(`docs/implementation-plan-waves-18-21.md` → PR26,
`feat/eval-behavioral-suite`, F94(b)) called for expanding to ≥6 behavioral
eval tasks across ≥3 project types before this release, specifically so the
suite could exercise all six defect classes and give runtime verification and
escape analysis something concrete to be scored against. The user chose to
ship the two Wave 21 mechanisms first and do that expansion as a follow-up
("Después hagamos la evaluación, hagamos el release") — this file records
that choice rather than fabricating a comparison the current suite cannot
support.
